# Паспорт проекта

**Команда:** ООО «тче наш». **Продукт:** ИП «ошла работа по полной» (техническое имя TaskFlow).
**Коды участников:** M1, M2, M3. Персональное соответствие передаётся преподавателю закрыто.
**Статус ранней калибровки:** черновик; подтверждения согласования в исходном архиве нет.
**Этап:** комплект для EK1. Состав подготовки и оставшиеся действия — [SUBMISSION.md](SUBMISSION.md).

## 1. Назначение

Небольшие команды назначают задачи и принимают результаты работы. Автор создаёт задачу для другого участника; исполнитель отправляет текстовый результат; автор принимает его или возвращает на доработку. Собственная предметная логика — разграничение полномочий и защищённый жизненный цикл результата.

## 2. Граница продукта

В продукт входят серверное API и PostgreSQL: регистрация, вход/выход, команды, членство, задачи, текстовые результаты, проверка доступа и переходов. Браузер или HTTP-клиент находится вне доверенной серверной границы. PostgreSQL — внутреннее хранилище продукта, а не внешний сервис.

Не входят: файлы, чат, комментарии, уведомления, дедлайны, диаграммы Ганта, внешние интеграции, мобильное приложение, восстановление пароля, удаление участников и переназначение задач. Полноценный графический интерфейс отложен; демонстрация выполняется HTTP-запросами и скриптом.

## 3. Пользователи и полномочия

| Контекст | Разрешено | Запрещено |
| --- | --- | --- |
| Анонимный клиент | Регистрация, вход, минимальный health-check | Данные и операции команд/задач |
| Зарегистрированный пользователь | Создать команду, работать в своих командах | Доступ к чужим командам |
| Создатель команды | Добавить существующего пользователя по его ID | Получать все задачи команды только на основании владения командой |
| Участник команды | Читать состав команды, создать задачу другому участнику | Добавлять участников, читать несвязанные с собой задачи |
| Автор задачи | Читать свою задачу; принять/вернуть результат на проверке | Отправлять результат вместо исполнителя |
| Исполнитель | Читать назначенную задачу; отправить результат из assigned/rework | Принимать результат; менять автора, исполнителя, команду |

Это контекстные отношения к объекту, а не глобальные роли в токене. Один пользователь может быть автором одной задачи и исполнителем другой. Для одной задачи автор и исполнитель обязаны различаться. Иначе запрет самостоятельной приёмки теряет смысл. Членство команды проверяется при каждом доступе. Административный API отсутствует.

## 4. Сквозные сценарии

1. **Назначение.** A создаёт команду, добавляет зарегистрированного B. A создаёт задачу для B. Сервер назначает authorId из сессии, state=assigned, version=1. В списке задачу видят только A и B.
2. **Приёмка.** B отправляет непустой результат и текущую version. Сервер сохраняет результат и review атомарно; A принимает текущую версию. Получается accepted, результат больше не изменяется.
3. **Доработка.** A возвращает review в rework. B отправляет новый результат, получая review. A принимает новую версию. При устаревшей версии возвращается 409; клиент перечитывает задачу и заново принимает осмысленное решение.

| Состояние | Действие | Кто | Следующее состояние |
| --- | --- | --- | --- |
| assigned (Назначена) | submit | Исполнитель | review |
| rework (На доработке) | submit | Исполнитель | review |
| review (На проверке) | accept | Автор | accepted |
| review | return | Автор | rework |
| accepted (Принята) | Любое изменение результата/состояния | Никто | Переходов нет |

Универсального редактирования полей задачи нет. Во время review результат заморожен.

## 5. Значимые данные

| Актив | Значение и последствия нарушения |
| --- | --- |
| Пароли и сессии | Компрометация позволяет действовать от чужого имени; хранятся только хеши |
| Членство и владелец команды | Подмена открывает доступ к чужой рабочей группе |
| Название, описание, результат задачи | Раскрытие нарушает конфиденциальность работы; подмена искажает сдаваемый результат |
| Автор, исполнитель, состояние, версия | Подмена позволяет принять чужую работу или обойти проверку; гонка делает решение автора недостоверным |
| Доступность API и БД | Недоступность прерывает назначение и приёмку задач |

## 6. Компоненты

Клиент → ASP.NET Core Web API → EF Core → PostgreSQL. Сервер проверяет сессию, членство, отношение к задаче, разрешённую операцию, состояние и версию. БД хранит данные и обеспечивает атомарность записи. Схема потоков и границ — [DFD.md](DFD.md). Проверку полномочий выполняет приложение, а не база данных.

## 7. Источники данных

Все параметры HTTP, включая ID в URL, JSON, версию и Authorization, недоверенные. Идентичность берётся только из найденной сервером действующей сессии. Автор, начальное состояние и версия новой задачи задаются сервером. Автор решения не приходит в JSON. Текст не исполняется как SQL/HTML. В БД значения передаются параметризованными запросами EF Core.

## 8. Минимальное ядро и фактический объём

Исходники содержат регистрацию/сессии, команды, добавление участников, создание/чтение задач, submit/accept/return и контроль версии. Это подготовленная реализация, а не заявление об успешном запуске. Статус проверок — [docs/VERIFICATION.md](docs/VERIFICATION.md).

Для EK1 достаточна запускаемая основа; полная реализация всех защит не обязательна. Можно отложить графический клиент, поиск, пагинацию сверх первых 100 записей, управление профилем. Нельзя удалить серверную логику разграничения действий автора/исполнителя из концепции продукта.

## 9. Стек и ограничения

C#, .NET 8, ASP.NET Core, EF Core, Npgsql.EntityFrameworkCore.PostgreSQL 8.0.4, PostgreSQL 16. Docker Compose упрощает локальный запуск. Новые для команды технологии из исходного паспорта: ASP.NET Core и EF Core.

Внешних бизнес-сервисов нет. Первое развёртывание требует доступа к реестрам контейнеров и NuGet; офлайн-запуск возможен после загрузки образов и сборки. В контейнере API запускается от непривилегированного пользователя. Демонстрационный HTTP доступен только на 127.0.0.1; публичное развёртывание требует TLS и отдельного эксплуатационного усиления по D-03.

## 10. Локальный запуск

Полные требования, команды, проверка и ожидаемые результаты: [README.md](README.md#запуск).
Простой запрос: GET http://127.0.0.1:8080/health → 200, JSON с status=ok и database=reachable.
Это подтверждает работоспособность API/БД, но не выполнение всех SR. Состояние ручных и автоматических проверок фиксируется отдельно.
